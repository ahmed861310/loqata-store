# متجر لقطة — الإصدار 2.1.0

## الجديد
- حساب عميل محلي على نفس الجهاز لحفظ الاسم والهاتف والعنوان.
- تعبئة بيانات العميل تلقائيًا عند إتمام الطلب.
- عرض الطلبات السابقة المرتبطة برقم الهاتف.
- لا يزال المشروع يعمل بدون خادم أو قاعدة بيانات خارجية.

## التشغيل
افتح `index.html` في المتصفح.


## الإصدار 2.2.0

- تحسين فصل واجهة الإدارة عن واجهة العميل.
- تنبيه واضح بأن القفل محلي وليس حماية لخادم أو قاعدة بيانات.

## الإصدار 3.3.0 — قاعدة بيانات وتسجيل دخول فعلي (نسخة تمهيدية)

أضيف خادم Node.js بدون مكتبات خارجية، مع قاعدة بيانات JSON محلية داخل `data/db.json`، وتسجيل دخول بجلسات Cookie، وتشفير كلمات المرور باستخدام `scrypt`.

### التشغيل

1. ثبّت Node.js 18 أو أحدث.
2. افتح مجلد المشروع في الطرفية.
3. شغّل: `npm start`
4. افتح: `http://localhost:3000`

### إنشاء حساب المدير لأول مرة

أرسل طلب POST إلى `/api/admin/bootstrap` يحتوي على `name` و`email` و`password` (10 أحرف على الأقل). بعد إنشاء المدير يصبح المسار مغلقًا.

> تنبيه: هذه نسخة تأسيسية للتجربة المحلية. قبل النشر الفعلي يجب استخدام PostgreSQL/MySQL، وHTTPS، ومتغيرات بيئة، وحماية CSRF، ومحددات محاولات الدخول، ونظام صلاحيات ومراجعة أمنيّة.

## v3.5.0 — OTP لتأكيد الهاتف
- الدفع عند الاستلام لا يُعتمد إلا بعد نجاح تحقق OTP من رقم الهاتف.
- الرمز صالح 5 دقائق، بحد أقصى 5 محاولات.
- يوجد حد لإعادة الإرسال ومعدل الطلبات.
- في التطوير المحلي يظهر الرمز في الواجهة لتسهيل الاختبار فقط.
- في الإنتاج يجب ضبط `NODE_ENV=production` و`OTP_WEBHOOK_URL` لربط مزود SMS؛ لا يتم إظهار الرمز في الإنتاج.
- لا تستخدم وضع التطوير للإطلاق العام.


## v3.6.0 — SMS OTP وربط مزود الرسائل
- ربط بدء الطلب بمرحلة OTP فعلية قبل إنشاء طلب الدفع عند الاستلام.
- تمرير `verificationToken` إلى الخادم، ولا يمكن إنشاء الطلب بدونه.
- دعم وضعين: `OTP_MODE=dev` للاختبار المحلي و`OTP_MODE=webhook` للإرسال عبر مزود SMS.
- عند الإنتاج يجب ضبط `OTP_MODE=webhook` و`OTP_WEBHOOK_URL` وعدم استخدام وضع التطوير.
- إضافة حد عام لكل عنوان IP لطلبات OTP، بالإضافة إلى حد الرقم نفسه.
- Cookie الجلسة تستخدم `Secure` تلقائيًا في الإنتاج.

### إعداد SMS
انسخ `.env.example` إلى `.env` أو اضبط متغيرات البيئة على الخادم:
- `NODE_ENV=production`
- `OTP_MODE=webhook`
- `OTP_WEBHOOK_URL=https://your-sms-adapter.example/send`

نقطة الـ webhook تستقبل JSON بالشكل: `{ "phone": "010...", "code": "123456", "message": "..." }` ويجب أن تعيد HTTP 2xx عند نجاح الإرسال.

## v3.8.0 — بنية بوابة الدفع الإلكتروني
- إضافة طبقة `payment-service.js` لفصل منطق بوابة الدفع عن الطلبات.
- إضافة `GET /api/payments/config` لمعرفة طرق الدفع المتاحة.
- إضافة `POST /api/payments/intents` كنقطة موحدة لبدء عملية دفع إلكتروني مستقبلًا.

- لا توجد بوابة دفع حقيقية مفعلة افتراضيًا؛ `PAYMENT_PROVIDER=none` يمنع تحصيل الأموال.

- لا تعتبر استجابة المتصفح دليلًا على نجاح الدفع؛ اعتماد الطلب الإلكتروني يجب أن يتم من webhook موثوق من مزود الدفع.
